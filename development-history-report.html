1. Executive summary

My personal portfolio at samarth-na.vercel.app / Cloudflare Workers is a single-page resume site: hero, profile, experience, projects, stack, research, and footer. I am Samarth Nagar — final-year B.Tech (Hons.) CS&T at SAGE University Indore (2023–27) — building a backend-focused identity (TypeScript, Node.js, SQL, WebSockets/WebRTC) around shipped projects like Cloud Workspace, SQL Visualizer, and Live Token Meter. This report tells how the site went from create-next-app to a minimal black design deployed on Cloudflare Workers in 71 calendar days but only about 10 active days of implementation.

This report consolidates everything. I read the full OpenCode session database for the project (46 sessions whose directories match the lineage portfolio-resume → website, including the 24 sessions under the current project id 39fc6fcbde8f94bcc50ec3f48268956bc8e8efb7), every assistant prose part (1,809 total messages, 1,355 for the core website project), both the git log and per-commit diffs (40 commits), the current source tree, and the package manifests. Each phase below names the sessions and commits that produced it — by stored title and by message subject — so every claim traces back to evidence.

The shape is not a straight line. June 20 built the initial light “dossier” theme and the Impeccable design-system experiment. July produced two textured exploration branches that never merged. The site then sat quiet for seven weeks. On August 24 it woke up: real resume content replaced the mock data, the dossier polish landed, and the data layer was centralized. August 28 created a parallel minimal black route at /minimal inspired by aarv.me and Diffshub. August 29 compressed roughly a dozen iterations into one day — hero grid fixes, rhythm normalization, declutter, font swaps, performance work that cut server memory from 5 GB to zero, and the promotion of minimal to /. That evening a typography lab tried five font faces before the system stack won. August 30 fixed the Workers build and wired real screenshots to every project card.

Three numbers frame the story. Roughly 6.2 million prompt-input tokens and 0.59 million output tokens (with another 105 million served from context cache, 111.8 M total) produced 2,971 lines of current source in 45 tracked files, at a recorded model spend of $4.68 for the full lineage ($0.97 for the core website project alone, heavily free-tier). Forty commits carry the result. And the distance between “looks right on my machine” and “ships right on the edge” — the gap this project kept falling into — closed only when builds were proven through opennextjs-cloudflare build producing .open-next/worker.js, not through local dev alone.

The earlier dossier theme, the five font variants, and the static-export detour are not wasted work. They are the controlled experiments that let the minimal system-stack landing survive — each alternative is traceable to a commit that was built, seen, and then deliberately deleted.

The repo's .gitignore handling of dist/ required two sessions to settle. Small frustrations got solved with archaeology later, but the pattern starts here: generative tooling leaves large artifacts that must be ignored early.

12. Phase 9 — Workers deployment

Sessions: OpenNext Cloudflare ENOENT for pages-manifest.json (muse-spark-1.2-contributor-free, 34 msgs, $0 but the diagnose that mattered, Aug 30 02:03), Personal Website /new-version Implementation Brief (muse-spark-1.2-contributor-free, 52 msgs, Aug 30 02:25–02:40), Create or update repository AGENTS.md instructions (muse-spark-1.2-contributor-free, 50 msgs). Commits: backup (ce62293, +864: adds wrangler.jsonc, open-next.config.ts, public/_headers), fix: remove static export config for Cloudflare Workers deployment (80e0e77, −4/2), fix: make Cloudflare Workers build produce .open-next for wrangler deploy (5e30774, +69/−42, the deployment fix).

Morning of Aug 30 broke the build. opennextjs-cloudflare build failed with ENOENT pages-manifest.json — the static-export config had erased the server manifest. Diagnosis in OpenNext Cloudflare ENOENT… was immediate: “output: 'export' and distDir: 'dist' produce a static-only build with no server manifest, which breaks createCacheAssets.”

Fixes landed in two steps. First, remove static export config deleted output: "export" and distDir so Next emits a server build for .open-next/worker.js. Then make Workers build produce .open-next made it stick: package.json build became opennextjs-cloudflare build, build:next became next build, and open-next.config.ts set buildCommand: "bun run build:next" to break recursion (build calling itself). Verified locally:

rm -rf .open-next .next && bun run build        → success, .open-next/worker.js 2.3K
rm -rf .open-next .next && npx opennextjs-cloudflare build → success
bunx biome check → 0 errors, 2 warnings (pre-existing)

wrangler.jsonc settled to main: ".open-next/worker.js", assets.directory: ".open-next/assets", compatibility_date: 2026-08-29, nodejs_compat + global_fetch_strictly_public flags, and the worker self-reference binding — formatted to space indent per biome. AGENTS.md and README.md gained a Build quirks section documenting the indirection so no future agent re-adds output: "export".

Cloudflare Workers Builds dashboard now documents: Build npx opennextjs-cloudflare build, Deploy npx opennextjs-cloudflare deploy (or bun run build via indirection). npx wrangler deploy auto-delegates to OpenNext when open-next.config.ts is present, but requires .open-next/ to exist first.

16. Easy, hard, and the debates

16.1 What was easy

  • Centralizing copy. One session, 33 messages, 490 ins — the JSON landed green with no follow-up fixes. Every later feature reused it for free.
  • Content replacement. 80 messages, one commit, no churn. Verified via gh links and biome clean. Resume-as-source-of-truth is a simple, fast spec.
  • Image wiring. Component already handled project.image; adding fields was purely data. The harder part — cropping fix — was a one-commit CSS change.
  • Mechanical deletions. Dossier and the 5-variant typography lab deleted cleanly; “delete is easy when the experiment is isolated” — the type-base.css overlap was scoped to .minimal so removal was surgical.
  • Reveal observer. 58 lines, progressive enhancement, reduced-motion respected — shipped once and never touched.

16.2 What was hard

  • Minimal's fit-and-finish. The “marathon” earned its name: two-column grid false-start, hero vacuum, projects rail pushing labels to viewport bottom, overlap (−64px), fonts hotlinked from aarv.me without cache, and a scroll-blocking overscroll-behavior bug. Each bug is trivial alone; four in one layout is a grind. Ten commits and the 246-message Checking /minimal page review carry the cost.
  • Typography taste. 7 commits over an evening just to end where the system stack started — SF Compact licensed, Onest correct but generic, Instrument close but extra axis, Schibsted heavy, Archivo condensed. The lab was not wasted; it proved the default is the least-wrong, not the most-exciting.
  • Workers build reversal. The perf optimization (static export) was correct in isolation and wrong for the deploy target; catching it required reading the OpenNext error, not the Next docs. The fix is small but the relitigating of next.config.ts costs attention twice.
  • Project ordering. After wiring images, a restore accidentally swapped content order; fixing it required a reorder commit that had to re-map images correctly — a classic silent data swap.
  • Early repo hygiene. dist/ committed, Impeccable's 49k-line import, stale validators polluting tsc --noEmit — none block shipping, all tax every later typecheck.

16.3 Where the user had to steer hard

  • Taste loops. Every minimal spacing and font call needed a screenshot round; the user demanded “high quality fonts, stable margins, great styling” and then supplied two reference images that the agent had to translate, not copy. The “this is a portfolio, not a freelancing pitch” edit is a content taste call only a human makes.
  • Asking “why.” “Reason for saving plans in ~/.opencode/plan/ directory” (6 msgs, 2 sec wall) and the later “Create or update repository AGENTS.md instructions” are meta-sessions where the user asks the system to explain itself — the project's best habit.
  • Font honesty. SF Compact cannot ship legally; the agent said so and offered alternatives rather than bundling the file anyway. That honesty is user-steered — the prior instruction was to steal the reference's style.

16.4 Where the model exceeded the ask

  • Self-verification traps caught before asking: stale-validator tsc noise called out as generated-artifact, not source error; port 3000 vs 3001 disambiguation for dev server verification; lint formatting done for every file before declaring done.
  • Honesty under taste pressure: reversing the guard-like static-export “win” within hours; flagging the image-aspect crop vs contain trade-off explicitly.
  • Evidence-first debugging: Workers ENOENT traced to pages-manifest.json expectation + fix verified with two independent clean builds (bun run build and npx opennextjs-cloudflare build), not just one.

16.5 Discussions and reasoning worth keeping

  • “Translate tokens, don't copy.” The minimal brief (“like aarv.me”) could have been a clone. The agent rebuilt spacing, fonts, and hierarchy from content constraints (8px scale, stepped headings) rather than lifting computed CSS — portability without copyright.
  • Zero-webfont decision. System stack as default is not the prettiest isolated type — Onest and Instrument both carry more character — but it is the only one with zero download, zero FOIT, and correct fallback via adjustFontFallback. Performance taste won.
  • Delete is a feature. Promoting minimal by deleting the dossier and 5 variants is cheaper to maintain than a toggle. Git is the feature flag.
  • Plan as carrier. The AGENTS.md commit threshold added mid-marathon prevented the classic git add -A sweep that would have merged untracked binaries into unrelated commits — the Cloud Workspace report calls this the “trap file” problem; this portfolio fixed it proactively on Aug 29.

17. Failure patterns and lessons

17.1 Patterns that repeatedly caused trouble

  1. Perf-and-deploy mismatch. Optimizations valid for one target (output: "export" for static hosts) break another (Workers need server output). The durable fix is AGENTS.md's Build quirks documenting the indirection, so the next agent reads why not to re-add export.
  2. Reference-image mimicry without validation. Hotlinking TWK Lausanne from aarv.me works in a browser, burns DNS+TLS per visit and violates the perf goal. Replaced with local variable fonts — lesson: inline assets from references only after measuring their cost.
  3. Overflow of generative artifacts. dist/ and stale .next/types/validator.ts were never source, but they polluted tsc --noEmit and git stat. .gitignore and generated-file hygiene must be first commits, not afterthoughts.
  4. Taste as unbounded spec. Without numbered, named iterations (“/1 stepped scale”, “star 11→16→18→13”), typography would have circled forever. Naming each attempt in commit subjects made comparison possible.
  5. Silent data swaps. Restoring content.json after a merge accidentally swapped project order and image mapping. No test catches this — only reading the JSON diff does. The reorder commit exists solely to fix a human-tool slip.
  6. Forks masquerading as new work. June 20 spawned three forks of “Create animated portfolio from resume” totalling $1.72 combined — all dropped. Later Aug→Sep sessions avoided forks via longer-lived sessions.
  7. Verification gap. Early on the dossier's reveal animation looked done but had overlapped ROLE/ORIGIN/STATUS text behind stacked lines; only a wide-viewport screenshot caught it. Browser screenshots, not curl 200, close the gap — same lesson as Cloud Workspace, smaller scale.

17.2 What worked, and should be credited

  • Strict static gates every change: biome check + biome format --write + tsc --noEmit (ignoring known-generated noise) before declaring done. Every commit before Workers was lint-clean.
  • Single JSON source of truth — the one constraint that compounded. It made minimal free and typography experiments isolated to CSS.
  • Small commits per visual change (≈30–150 lines) with explicit messages (“sharpen project shots”, “show full screenshots without cropping”). Bisectable and revertable.
  • Vendor-font honesty: the SF Compact answer could have silently bundled a licensed file; refusing and offering Instrument was the right call and was documented rather than hidden.
  • Build verification at the target — bun run build and npx opennextjs-cloudflare build both producing .open-next/worker.js 2.3K — declared only after both succeed.
